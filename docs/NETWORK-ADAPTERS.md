# 网络调优方案

## 使用

通过「网络 → 网络调优 → 调优方案」或 `keine tuning-adapters` 选择提供方。输入参数后查看运行值与目标值的差异，确认后应用；从相同入口重新配置、切换或撤销。两套方案互斥，不会拼接算法或叠加上一方案独有的参数。

| 方案 | 输入 | 计算与参数 |
| --- | --- | --- |
| tcpfit 0.5.9 | 可用带宽、业务 RTT、代理 / 大文件 / 混合角色 | 原始 BDP、内存预算、默认缓冲区计算及基础 sysctl 参数 |
| vps-tcp-tune 5.4.11 | 可用带宽、亚太 / 美欧地区 | 原始带宽地区档位、TIME_WAIT 桶计算、内存与调度 sysctl 参数 |

带宽填写业务可用 Mbps，不是虚拟网卡的标称速率。tcpfit 的 RTT 默认为 150 ms，并非自动测量；按主要用户到 VPS 的典型延迟填写，多运营商或时段差异较大时需分别比较效果。地区档位是上游的策略假设，不是自动识别所在地或实时网络预测。

## 集成范围

计算函数固定在经过审查的上游提交；完整版本、提交与 MIT 授权见 [第三方声明](THIRD-PARTY-NOTICES.md)。上游更新不会自动下载或以 root 执行，需要审查差异并更新适配代码。

两套 **sysctl 参数策略** 保留各自计算规则，不拼接算法。keine 接管输入、预览、冲突检查、文件写入、状态核对和恢复，并将测量、实际队列和路由窗口纳入统一管理；不是上游脚本的全功能复制。

- 已接入四流带宽探测、用户指定对端的延迟比较、指定区间的粗扫/复扫、单流/四流验证、FQ / mq 叶队列、HTB + FQ 整形，以及 initcwnd / initrwnd。
- 扫描保留 tcpfit 的 0.1% 重传阈值、干净本底五倍且最高 1% 的异常阈值、三次中至少两次异常确认，以及分档余量和 burst 计算；使用明确输入区间，不复制上游公共节点库、自动区间猜测或自动套用整形。
- vps-tcp-tune 的 XanMod 安装、DNS、Realm、端口配额、计划重启、MSS clamp、RPS/RFS、THP 和文件描述符修改不随参数方案执行。
- `default_qdisc=fq` 是内核默认队列设置，不等于现有网卡队列已替换；实际队列从「队列与初始窗口」单独配置，状态页另列 `tc qdisc`。
- vps-tcp-tune 要求内核已有 BBR；可单独确认加载当前内核的 tcp_bbr 模块，不安装内核。tcpfit 沿用上游的 BBR / cubic 选择。
- tcpfit 内存页公式按 4 KiB 计算，不匹配的系统明确拒绝，不擅自更改算法。
- 不可读取的可选内核参数在预览中列出并跳过；必要参数缺失时停止。实际写入被拒绝时回退整个事务，不隐藏部分失败。

参数方案可能改变所有新建或现有 TCP 连接的行为，也可能降低特定线路的表现。公式一致不等于实际吞吐保证；应保留服务商控制台，按实际业务进行前后对比。

## 测量与配置

在 `keine tuning-adapters` 中进入「按需测量」或「队列与初始窗口」。

| 操作 | 用途 | 修改范围 |
| --- | --- | --- |
| 带宽探测 | 四流测试指定对端的接收速率，给出参数输入参考 | 临时 FQ，结束后恢复 |
| 限速拐点扫描 | 输入下限、上限与步长，确认重传变化后生成候选值 | 临时 HTB + FQ，结束后恢复 |
| 当前效果验证 | 在当前配置下分别测单流、四流吞吐与重传 | 不改队列或参数 |
| 对端延迟比较 | 比较最多八个自选主机的 ICMP 平均 RTT | 不改配置，不保证对端支持测速 |
| FQ 队列 | 调整当前网卡的实际调度方式 | 单队列 FQ 或 mq 下逐个 FQ 叶队列 |
| HTB 总出口限速 | 按 Mbps 限制整张网卡出口 | 包含 SSH、TCP、UDP 和代理业务 |
| TCP 初始窗口 | 调整新建 TCP 连接的初始窗口，默认参考 32 段 | 指定 IPv4/IPv6 默认路由的 initcwnd / initrwnd |

测速端需要 `iperf3`、`jq`、`iproute2` 和 GNU `timeout`，缺少时从软件中心单独安装。对端必须是允许你使用的 iperf3 服务；例如另一台你控制的服务器按需运行 `iperf3 -s`，并自行检查云端和本机防火墙。keine 不启动后台测速服务器，不自动开放端口，也不探测随机公网主机。

每轮可选 3–30 秒；扫描粗扫最多 13 档，再按需要细扫和复测。开始前显示保守时间预算及扫描流量估算。探测与效果验证不限制速率，可能产生大量流量。公网节点的负载、运营商路径和时段都会影响结果；低于目标 70% 的干净样本不能成为推荐限速档，失败样本不会当作零重传。显示的百分比按重传数和估算报文数计算，不是实际丢包率。

建议先验证现状，再选参数方案；只有证据支持限速时才手动设置 HTB，最后重复验证。选择 FQ 会解除当前托管 HTB。不要在同一网卡上同时使用其他调优工具。

## 持久化与撤销

sysctl 托管配置为 `/etc/sysctl.d/99-keine-tuning.conf`，通过系统原生 sysctl.d 加载。实际队列和路由窗口 **仅当前启动周期有效**，重启后不自动重放；没有新增 daemon、Cron、Timer、开机钩子或测速任务。退出控制台后不保留项目进程。

首次修改前的运行值、文件原始状态与最后项目值记录在 `/var/lib/keine/changes`。这是一份撤销基线，不是每次操作创建历史备份。手动备份仍在备份中心单独创建。

队列和路由窗口记录位于其下的 `network-runtime`，按网卡与资源独立管理。记录验证启动 ID、网卡索引/地址及最后项目状态；重启后的旧记录只能清理，不能覆盖本次启动的网络。正常测速结束、失败或可捕获的中断会尝试恢复测速前状态；强制杀进程、断电或内核拒绝恢复不能保证自动回退，应通过服务商控制台检查。

队列接管只支持已知的 FQ、FQ-CoDel、默认 pfifo_fast、mq，以及项目托管的 HTB。无法完整解释的选项、外部过滤器、ingress/clsact 或自定义调度树会停止接管。恢复保留调度策略、支持的参数和多队列结构；内核对象句柄、排队报文与历史计数器不保留。路由仅支持主表中单条、无多路径、无动态到期的默认路由；不修改网关，不自动安装或重载内核。其他工具在运行中改写网卡可能造成冲突，恢复不会强行覆盖已识别的外部修改。

应用前检查已有独立 BBR / 手动参数、已知上游持久服务，以及 /etc、/run 中重叠的 sysctl 声明。遇到冲突停止并显示来源，不注释或删除第三方文件。此检查不能识别所有未知脚本的运行钩子，也不能保证以后不会有其他管理器重写设置。

切换时，新方案之外的旧参数恢复首次基线；共用参数继续保留同一份初始记录。配置文件原子替换，运行值逐项核对；失败时尝试恢复操作前的运行值和文件。无法回退时保留记录并报告，不宣称成功。

「撤销参数方案」只撤销 sysctl 参数；队列与初始窗口从对应页面单独撤销。「备份与恢复 → 项目变更」以及「撤销已记录修改并卸载」同时包含参数组和网卡运行配置。仅卸载程序不会撤销系统设置。外部修改、缺失基线或文件损坏会停止自动恢复，不猜测内核默认值。

## 扩展结构

- `src/integrations/network-tuning/upstream/`：固定的上游计算函数，不执行原脚本入口。
- `plans.sh`：独立参数计划、输入验证、内核支持过滤。
- `transaction.sh`：互斥、冲突检查、事务应用、切换与恢复。
- `device.sh`：队列与默认路由的可恢复快照、写入和核对。
- `runtime.sh`：网卡归属、首次基线、运行事务与临时测量恢复。
- `measure.sh`：有界前台测量、JSON 结果校验、探测/扫描/验证。
- `menu.sh` / `advanced-menu.sh`：统一交互、差异预览、测量预算和运行配置管理。

新提供方必须声明完整写入范围，提供独立计划和恢复检查；不通过远程 source、eval 或任意 URL 执行器接入。回归测试使用系统临时目录和替身 sysctl，退出时清理，测试源码不部署到 VPS。

命令语义参考：[iperf3](https://software.es.net/iperf/invoking.html)、[FQ](https://man7.org/linux/man-pages/man8/tc-fq.8.html)、[HTB](https://man7.org/linux/man-pages/man8/tc-htb.8.html)、[ip route](https://man7.org/linux/man-pages/man8/ip-route.8.html)。
