# 网络调优方案

## 使用

通过「网络 → 网络调优 → 调优方案」或 `keine tuning-adapters` 选择提供方。输入参数后查看运行值与目标值的差异，确认后应用；从相同入口重新配置、切换或撤销。两套方案互斥，不会拼接算法或叠加上一方案独有的参数。

| 方案 | 输入 | 计算与参数 |
| --- | --- | --- |
| tcpfit 0.5.9 | 可用带宽、业务 RTT、代理 / 大文件 / 混合角色 | 原始 BDP、内存预算、默认缓冲区计算及基础 sysctl 参数 |
| vps-tcp-tune 5.4.11 | 可用带宽、亚太 / 美欧地区 | 原始带宽地区档位、TIME_WAIT 桶计算、内存与调度 sysctl 参数 |

带宽填写业务可用 Mbps，不是虚拟网卡的标称速率。tcpfit 的 RTT 默认为 150 ms，并非自动测量；按主要用户到 VPS 的典型延迟填写，多运营商或时段差异较大时需分别比较效果。地区档位是上游的策略假设，不是自动识别所在地或实时网络预测。

## 集成范围

计算函数固定在经过审查的上游提交；完整版本、提交与 MIT 授权见 [第三方声明](THIRD-PARTY-NOTICES.md)。上游更新不会自动下载或以 root 执行，需要审查差异并更新适配代码。

本次接入的是两套 **sysctl 参数策略**，不是上游脚本的全功能复制。保留各自计算规则；keine 接管输入、预览、冲突检查、文件写入、状态核对和恢复。

- tcpfit 的自动测速、sweep 拐点扫描、HTB 整形和 initcwnd 路由钩子不在本次接入范围。
- vps-tcp-tune 的 XanMod 安装、DNS、Realm、端口配额、计划重启、MSS clamp、RPS/RFS、THP 和文件描述符修改不随参数方案执行。
- `default_qdisc=fq` 是内核默认队列设置，不等于现有网卡队列已替换；状态页另列实际 `tc qdisc`。
- vps-tcp-tune 要求内核已有 BBR；可单独确认加载当前内核的 tcp_bbr 模块，不安装内核。tcpfit 沿用上游的 BBR / cubic 选择。
- tcpfit 内存页公式按 4 KiB 计算，不匹配的系统明确拒绝，不擅自更改算法。
- 不可读取的可选内核参数在预览中列出并跳过；必要参数缺失时停止。实际写入被拒绝时回退整个事务，不隐藏部分失败。

参数方案可能改变所有新建或现有 TCP 连接的行为，也可能降低特定线路的表现。公式一致不等于实际吞吐保证；应保留服务商控制台，按实际业务进行前后对比。

## 持久化与撤销

唯一托管配置为 `/etc/sysctl.d/99-keine-tuning.conf`，通过系统原生 sysctl.d 加载；没有新增 daemon、Cron、Timer 或测速任务。退出控制台后不保留项目进程。

首次修改前的运行值、文件原始状态与最后项目值记录在 `/var/lib/keine/changes`。这是一份撤销基线，不是每次操作创建历史备份。手动备份仍在备份中心单独创建。

应用前检查已有独立 BBR / 手动参数、已知上游持久服务，以及 /etc、/run 中重叠的 sysctl 声明。遇到冲突停止并显示来源，不注释或删除第三方文件。此检查不能识别所有未知脚本的运行钩子，也不能保证以后不会有其他管理器重写设置。

切换时，新方案之外的旧参数恢复首次基线；共用参数继续保留同一份初始记录。配置文件原子替换，运行值逐项核对；失败时尝试恢复操作前的运行值和文件。无法回退时保留记录并报告，不宣称成功。

「备份与恢复 → 项目变更」将调优作为整组资源撤销；「撤销已记录修改并卸载」也包含该组。仅卸载程序不会撤销系统设置。外部修改、缺失基线或文件损坏会停止自动恢复，不猜测内核默认值。

## 扩展结构

- `src/integrations/network-tuning/upstream/`：固定的上游计算函数，不执行原脚本入口。
- `plans.sh`：独立参数计划、输入验证、内核支持过滤。
- `transaction.sh`：互斥、冲突检查、事务应用、切换与恢复。
- `menu.sh`：统一交互、差异预览和只读状态。

新提供方必须声明完整写入范围，提供独立计划和恢复检查；不通过远程 source、eval 或任意 URL 执行器接入。回归测试使用系统临时目录和替身 sysctl，退出时清理，测试源码不部署到 VPS。
