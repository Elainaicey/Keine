# 原生集成与可逆操作契约

## 边界

“已安装”“可控制”“由项目创建”是不同状态。原生集成可以查询或控制主机已有软件；只有经过验证的项目资源才允许清理。软件检测不能以项目标记作为唯一依据，程序名也不能作为删除依据。

WARP 适配器支持官方 `warp-cli` 和已有 wgcf/WireGuard 配置。不会猜测任意第三方脚本的安装地址，不加载配置为 Shell，也不展示私钥。未启用过的 systemd 模板实例使用 `LoadState` 补充识别，仍通过标准服务控制接口操作。

## 扩展流程

1. 在 `config/integrations.tsv` 声明六个字段：ID、名称、后端、探测入口、处理器、描述。
2. 在 `src/integrations/` 实现探测、状态解析和动作适配，加载到 `src/integrations.sh`。
3. 将处理器加入 `integration_dispatch` 白名单。配置文件和远程文本永远不能通过 `eval` 执行。
4. 复用原生 CLI、systemd 和 core 能力，限定超时，不复制安装流程，不创建后台监控。
5. 每个写操作说明影响并确认；可恢复设置必须可靠读取原值，不支持恢复的动作明确标记。

第三方脚本不等同于原生适配器。将来接入必须固定上游、校验资产、明确参数与写入范围；不能仅保存一个 URL 后直接以 root 执行。支持识别现有安装，不承诺替上游恢复未声明副作用。

## 变更记录

`src/core/changes.sh` 保存首次写入前的文件状态和本项目最后写入的指纹。配置快照用于历史恢复，变更记录用于撤销项目操作，两者不能混为一谈。

- `changes_prepare_file PATH [directory]` 必须在修改之前调用；已有目录不能整目录接管，新建目录按父级整体记录，避免父子重复恢复。
- `changes_commit_pending` 在动作审计时更新最后状态，失败路径也应登记已经发生的改动。
- `run` 为主机名、时区、NTP、root Shell、BBR/默认队列、白名单网络参数、UFW 与标准服务生命周期挂接原生设置记录。绕过 `run` 的写操作必须显式登记。
- APT 安装前后比较已安装包；仅新增包登记为可清理对象，项目更新这些包时同步版本。原有包升级不声称可回滚。
- WARP 连接只能在解析到稳定的 Connected/Disconnected 状态时记录，异步连接需要回读确认。
- 预览不能写入基线、审计或软件标记。单项恢复配置不自动重载业务服务；整体恢复对 SSH/UFW 执行相应验证与加载，系统 DNS 使用对应原生后端加载。

网络中心还提供尚未绑定上游的第三方调优入口，只观察参数和配置来源。后续开发需要遵守 [网络调优适配契约](NETWORK-ADAPTERS.md)；外部脚本执行不在当前能力内。

恢复先检查冲突。当前指纹既不是原始状态也不是项目最后状态时，默认拒绝覆盖；用户可保留资源并解除记录。新增包清理先模拟依赖事务，不得连带移除主机原有软件包。

## 不可推断的内容

旧版没有记录的变化、原有包升级或删除、数据库或容器业务数据、主动销毁的数据、系统日志和上游未声明的安装副作用无法靠卸载程序自动逆转。项目必须保留这条边界，不能以“全量卸载”名称作出虚假的恢复承诺。

临时测试夹具应位于系统临时目录并由退出处理器删除；`tests/` 是保留的离线回归源码，不打包到 VPS 安装目录。
