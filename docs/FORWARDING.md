# TCP / UDP 端口转发

入口：**网络管理 → TCP / UDP 转发**，或 `keine forward`。

## 创建规则

1. 通过「安装 / 更新 socat」安装转发组件。
2. 选择「新建转发」，填写规则名称、协议、监听 IP 和端口、目标 IP 和端口。
3. 检查转发方向后确认应用。运行中的服务通过监听检查后才报告成功。

默认监听 `127.0.0.1`，只允许本机连接。对外提供服务时可填写指定本机 IP、`0.0.0.0`（全部 IPv4）或 `::`（全部 IPv6）。IPv6 输入不加方括号；IPv6 监听仅接收 IPv6，不隐式占用 IPv4。

例如：TCP `0.0.0.0:2443` → `192.0.2.10:443`。示例目标是文档保留地址，使用时替换为实际目标。

公网使用前必须在主机防火墙和云平台安全组放行相应端口与协议。可从规则详情进入主机防火墙配置。转发功能不自动创建或删除防火墙规则，避免误改已有访问控制。没有认证的后端不应直接公开；按需要限制来源。

## 管理与恢复

- 修改协议、端点或 UDP 空闲回收时间；运行中的规则修改目标会中断原连接。
- 启动、停止，单独切换开机启动。新规则默认立即运行，不启用开机启动。
- 查看原生 Journal 日志、检查 TCP 目标、刷新实际运行状态。
- 删除时停止并禁用对应服务，移除配置及其恢复记录；保留 socat 和独立配置的防火墙规则。
- 「备份与恢复 → 项目变更记录」使用相同安全删除流程撤销转发资源。

每条规则对应 `/etc/systemd/system/keine-forward-名称.service`。元数据按固定字段读取，不作为 Shell 代码执行。写入前检查路径、端口和服务来源，写入后执行 systemd 验证并加载；失败回退本次配置和此前的运行、开机状态。遇到外部编辑、同名外部服务、drop-in 或缺失归属记录时停止接管。

keine 本身不创建监控或定时任务。用户明确启用的转发由 systemd 管理并持续运行；它是业务服务，而不是后台监控。仅卸载工具会保留业务服务；选择撤销项目变更再卸载才会移除已记录的转发。

## 边界

- 一个规则只处理一种协议、一个监听端点和一个目标。TCP 与 UDP 同端口使用两个不同名称的规则。
- 目标目前使用 IP，不接管 DNS、路由、透明代理或现有 NAT。支持 IPv4 与 IPv6 间转发，目标看到的是 VPS 出站地址，不保留客户端源 IP。
- 使用 socat 用户态转发，每条规则最多 128 个并发会话，适合小规模按需转发，不承诺高并发或满带宽性能。
- UDP 默认 120 秒无流量回收会话，可设置 1–3600 秒；无握手，不能通过一次连接探测证明业务可用，应发送真实业务流量验证。
- 不改变 TLS 内容或终止 TLS，不能替代反向代理的域名路由和证书管理。
- 为避免监听与开机冲突，同一协议、地址族下的已使用端口保守视为占用，不自动停止其他服务。
