# FRP 隧道管理

入口：`keine frp`、「网络管理 → FRP 隧道」或「应用与容器 → FRP 隧道」。软件中心的 `frps`、`frpc` 详情可直接进入对应实例。

FRP 由可被客户端访问的服务端 `frps` 和能访问目标服务的客户端 `frpc` 组成。客户端主动连接服务端，访问服务端映射端口的请求通过隧道到达客户端侧目标。普通单机转发使用 [TCP / UDP 转发](FORWARDING.md)；FRP 适合需要客户端主动建立隧道的场景。

## 首次部署

1. 在服务端进入 `keine frp → 服务端 frps → 安装 / 更新软件`，安装官方 `frps`。
2. 创建服务端配置：控制连接默认监听 `0.0.0.0:7000`，允许映射端口默认 `10000–20000`，映射默认仅监听 `127.0.0.1`。允许范围不能包含控制端口。
3. 连接令牌可自行输入；新服务端留空会生成随机令牌。保存后从「查看连接令牌」明确确认显示，安全地传给客户端。普通状态、操作审计和项目日志视图隐藏令牌。
4. 在客户端安装官方 `frpc`，配置服务端 IP 或域名、控制端口、唯一客户端标识和相同令牌。首次创建可选择暂不启动；运行验证需要对端已经可达。
5. 在客户端添加映射，例如 `web / tcp / 127.0.0.1 / 8080 / 10080`，表示服务端 `10080` 转到客户端侧 `127.0.0.1:8080`。目标也可以是客户端可访问的局域网 IP、IPv6 或域名。
6. 在服务端明确配置所需防火墙和云端安全组。若映射保持监听本机，可从服务端详情进入反向代理与 HTTPS，将站点上游设为 `127.0.0.1:10080`。需要直接公网访问时，显式将映射监听改为 `0.0.0.0` 或 `::`，并只放行所需端口。
7. 分别检查服务端、客户端及实际业务响应；需要重启后恢复隧道时，在两端各自开启开机启动。

新实例默认立即启动但不开机启动；安装二进制本身不创建服务。工具不会自动修改防火墙、NAT、系统 IP 转发或云端规则。IPv4/IPv6 的可达性取决于两端网络与所选监听地址，不保证 `::` 在所有系统同时接受 IPv4。

## 实例与映射

- 每台主机支持一个托管服务端和一个托管客户端。二者可共存，也可分别部署在两台主机。
- 客户端提供 TCP / UDP 映射列表、添加、修改、停用、启用和删除，最多保存 64 条映射。名称及客户端标识需以小写字母开头，最多 32 位，只含小写字母、数字和连字符。
- 同一客户端启用映射不能重复占用同协议的远端端口；TCP 与 UDP 可以使用相同端口号。远端实际占用和允许范围由服务端最终检查，客户端启动需确认全部启用映射注册成功。
- 停用映射保留参数但不生成生效的代理配置。修改配置或映射会重启该实例，中断该客户端的全部现有隧道；切换开机策略保持当前运行状态。
- 实例页包含运行状态、配置检查、连接检查、最近日志、启动/停止、重启、开机策略以及软件、防火墙和反代入口。

当前范围为基于 TCP 控制连接的 TCP / UDP 端口映射，不提供 HTTP/HTTPS 虚拟主机、STCP/XTCP、QUIC/KCP、多实例模板、Dashboard 或任意自定义 TOML 编辑。应用级 HTTPS 可通过现有反代管理配置。

## 安装来源与已有实例

`frps`、`frpc` 分别作为软件中心条目，复用 `fatedier/frp` 最新稳定 GitHub Release、精确 Linux amd64/arm64 资产、API SHA-256 digest、安装后版本和二进制完整性检查。更新由用户主动触发，先停止对应托管实例；更新后从 FRP 管理启动并验证。两个条目独立更新，不保证未升级对端兼容任意未来版本。

「识别已有实例」只读列出 PATH 中的命令、常见 `frps.service` / `frpc.service`、托管服务、`/etc/frp` 与 `/home/frp` 常见配置路径及名称含 frp 的 Docker 容器。它不读取配置内容，不承诺发现所有自定义实例，不自动接管或迁移这些实例。存在运行中的常见外部服务时，阻止软件替换；自定义服务需先人工核实其使用的二进制。软件中心仍保留明确确认后接管外部二进制的既有流程，二进制接管不等于配置接管。

工作流参考 [科技 lion](https://github.com/kejilion/sh)，实现使用 [FRP 官方项目](https://github.com/fatedier/frp) 和 [官方配置说明](https://gofrp.org/en/docs/features/common/configure/)，不执行第三方脚本或安装第三方镜像。

## 配置、安全与撤销

| 资源 | 路径 / 行为 |
| --- | --- |
| 官方程序 | `/usr/local/bin/frps`、`/usr/local/bin/frpc`，由软件中心独立管理 |
| 服务端配置 | `/etc/keine-frp/frps.toml`，权限 `0600` |
| 客户端配置 | `/etc/keine-frp/frpc.toml`，权限 `0600`，包含映射与令牌 |
| 服务定义 | `/etc/systemd/system/keine-frps.service`、`keine-frpc.service`，权限 `0644` |
| 归属记录 | 项目状态目录中的首次基线与最后写入指纹 |
| 日志 | 原生 systemd Journal，按用户操作读取，无项目监控进程 |

令牌为 16–128 位字母、数字、下划线或连字符，输入不回显，原生配置校验错误不直接展示配置值。TLS 在客户端启用、服务端强制要求，认证涵盖登录、心跳和新建工作连接。当前使用 [FRP 默认 TLS 机制](https://gofrp.org/en/docs/features/common/network/network-tls/)，**没有配置自定义 CA 或服务端证书身份校验**；传输加密不能视为已验证服务端身份，需使用可信网络和受控端点。令牌拥有服务端允许端口范围内的映射权限，请只授予可信客户端；客户端标识用于区分代理名称，不是独立账户权限边界。

服务以 root 运行以读取受保护配置及按需绑定低端口，并限制能力集、文件系统写入与设备访问。日志视图隐藏当前令牌；历史 Journal 属于原生系统日志，工具不清理或重写它，也不承诺清除旧令牌或外部程序写入的敏感内容。

写操作有并发锁，先运行官方 `verify -c` 和 `systemd-analyze verify`，再成组部署 TOML 与 Unit。服务端启动需确认控制端口属于服务进程；客户端启动需确认本次进程登录与全部启用映射注册。失败或可捕获中断会尝试恢复此前两个文件、运行状态和开机策略；恢复失败保留权限受限的临时副本并提示路径。断电、SIGKILL 或文件系统故障不保证自动恢复。

只管理本项目创建、有完整记录、内容与权限未被外部修改的配置和 Unit。遇到外部修改、符号链接、其他来源 Unit 或 drop-in 时停止覆盖；事务中的外部修改也不会被失败回退覆盖。需要自定义配置时请使用独立原生实例。

「移除托管实例」停止服务并成组移除配置、映射和 Unit，保留软件二进制与独立防火墙规则。删除二进制前须先移除实例。恢复中心将实例作为一个条目处理，整体撤销先移除实例，再撤销二进制；外部冲突阻止撤销。仅卸载 keine 程序保留业务服务及状态记录；直接清除项目数据会丢失撤销记录，需要自动移除业务资源时应选择「撤销已记录修改并卸载」。

## 验证边界

连接检查分别显示配置/归属、服务端监听或客户端本次启动注册，并探测控制端口与客户端 TCP 目标。启动成功日志只能证明该次进程曾经登录和注册，不能替代当前业务验证。UDP 必须使用真实业务报文检查；防火墙、安全组、远端目标响应与真实链路都可能影响结果。

离线回归覆盖参数、凭据隐藏、配置生成、映射管理、服务状态、并发拒绝、成组回退、外部冲突和恢复入口。它使用模拟 systemd/FRP，不代表真实部署通过。当前开发环境尚未完成 Linux VPS 上的实际 systemd、TCP / UDP 流量和 IPv4/IPv6 跨地址族验证；支持符号链接的 Linux 环境还会执行完整链接拒绝用例。
